# Physical data ledger

Generated by `python3 tools/nagano_data.py map baseroms/us/baserom.z64 analysis/data_map`
(plus the unit verification logs).

`rom_map.tsv` is a half-open, gap-free, non-overlapping interval map of the
12,582,912-byte retail ROM. Every non-code byte has one category and stage, and
`tools/nagano_data.py reconstruct` regenerates every non-code interval from its
structured representation and compares it byte-for-byte with the ROM.

| Category | Bytes |
|---|---:|
| ROM header / IPL3 boot | 4,096 |
| Executable code (CPU text, RSP microcode, overlay text; owned by code matching) | 796,368 |
| Code-unit data (jump tables, overlay data) | 53,129 |
| Initialized data | 92,001 |
| Read-only data | 27,964 |
| Pointer / offset tables | 4,976 |
| Strings | 362 |
| s16x6 record streams (raw file-table entries) | 86,400 |
| libaudio banks and VADPCM samples | 3,149,970 |
| Konami-LZ containers (asset files and music sequences) | 8,035,702 |
| Proven zero padding | 331,944 |
| Unknown | 0 |

Physical byte-exactness and nested decoding are separate claims. The 547 LZ
containers re-encode exactly from their decoded payloads. `nested_map.tsv` is a
gap-free logical-byte map of the 14.76 MB asset payload, generated by
`tools/generate_nested_map.py`; `nested_summary.tsv` preserves the per-file
unknown and unreferenced-zero counts. Typed F3DEX regions round-trip, while
787,597 logical bytes remain explicitly unknown.

All non-function data decompilation required for an exact ROM reconstruction is
complete. Here, `unknown` means that a decoded payload range has no proven
semantic type; it does not mean that its bytes, container boundary, compression,
or reconstruction are unknown. These ranges must remain conservatively labeled
until code references or format evidence prove a narrower classification.

The 23 music-sequence payloads have a proven outer structure: a leading
big-endian `u16` offset table identifies 297 tracks in total. The track counts
come from `D_80074680`, exactly as reconstructed `func_80049A78` consumes them.
`tools/nagano_sequences.py` verifies and round-trips every offset table, track
boundary, and Nagano/Konami event. It accounts losslessly for 33,236 events
and 86,509 event-stream bytes; command behavior beyond the proven token grammar
remains separate semantic work.
